# Agent Note: Composer 模型列表的提供方折叠项

Status: implemented

[English](2026-08-17-composer-provider-group-disclosure.md) | 中文

## Problem

Composer 的模型 slot 过去把所有提供方公布的所有模型渲染成一条扁平的滚动列表，提供方名称只是其上的 sticky 标题。因此一个公布大量模型的提供方会把其余提供方挤到远低于可视区的位置，而菜单自身 360px 的高度上限又让提供方之间的比较变成滚动操作。`/model` 弹出框没有这个问题，因为它的外壳会按输入文本过滤行；而 slot 菜单没有过滤，列表长度是用户与提供方之间唯一的阻碍。

## Decision

**模型面板中每个提供方分组都是一个可展开项。** 原来的标题 `<div>` 变成 `role="menuitem"` 按钮，带 `aria-expanded` 与指向其模型列表的 `aria-controls`、一个旋转的箭头、提供方名称，以及该分组的模型数量。折叠状态下一个提供方只占一行，同时仍然报告它包含多少模型。

**当前选择所在的提供方默认展开。** 展开状态读取 `disclosed[groupId] ?? groupId === current.provider`，因此覆盖记录中不存在的分组仍然遵循该默认值——即使它来自菜单打开之后才返回的加载：目录在每次打开时刷新，而提供方拓扑可能在常驻菜单之下发生变化。关闭菜单会丢弃这些覆盖，因此每次打开都从会话实际所在的位置开始，而不是从上一次浏览留下的状态开始。

**折叠的模型完全不进入菜单。** 它们不被渲染，因此既有的方向键环——由 `itemRefs` 的注册顺序构成——只会走过提供方标题和可见选项，折叠的提供方不可能通过隐藏的 radio 获得焦点。

## Alternatives considered

**在扁平列表上加文本过滤。** 本次变更中拒绝：它把 `/model` 弹出框已有的能力复制进一个 240px 的菜单，而且帮不到那种想先看清有哪些提供方、再说出模型名的用户。两者并不冲突；过滤框可以之后加在分组上方。

**默认折叠所有分组，包括当前选择所在的分组。** 拒绝，因为该 slot 的首要职责是显示会话当前所在的位置；全部折叠的面板恰好隐藏了回答这个问题的勾选行。

**用模型数量阈值决定哪些分组折叠。** 作为隐藏可调项拒绝——这个数字会是一个随部署而变、却没有配置字段承载的选择，而且菜单会因为用户看不见的原因而展开或折叠。

**在多次打开之间保留展开状态。** 拒绝，因为该状态会在失去意义之后继续存在，而界面上没有可见的控件把它重置；过期的展开状态也与"指向当前选择"这一默认行为相互矛盾。

## Consequences

拥有多个提供方的用户先看到提供方列表，再向下钻取其中一个；只有单一提供方的会话，除了标题上多出的箭头和数量之外没有变化。该 slot 的键盘环现在包含提供方标题，因此在折叠状态下遍历多提供方目录的路径更短，展开状态下与此前完全一致。提供方名称仍然只用于显示，选择、目录与 wire 行为均不改变：本次变更完全位于 `ModelSelect` 内部。
